# GL BOT

카카오톡 게임·관리·홍보와 웹사이트를 하나의 PostgreSQL에 연결합니다.

## 실행

Node.js 22.8 이상 또는 24에서 `npm ci`, `npm start`를 실행합니다. Railway의 기존 DATABASE_URL, KAKAO_AUTH_PATH, 인증 파일 복원 명령은 유지합니다. hz-new.js가 봇과 HTTP 서버를 함께 실행하며 PORT는 Railway 값을 사용합니다. src/를 빌드한 dist/는 배포 시 생성합니다.

- `/`: 공개 게임 소개, 동의한 별명만 보이는 랭킹, 공지, 이용 안내
- `/admin`: 운영자 로그인 및 사용자·코인·채팅방·홍보·공지·감사 기록 관리
- `/promo/`: 초대받은 이용자가 카카오 QR로 본인 계정에 로그인하여 본인 전체 방에서 홍보하는 전용 웹. [초대·사용 방법](docs/홍보웹-사용안내.md)
- `/health`: 게임/DB 초기화와 카카오톡 연결 상태
- `GL_WEB_ENABLED=0`: HTTP 서버만 비활성화

봇 계정에서 !게임작동 / !게임중지, !관리작동 / !관리중지를 사용합니다. 게임과 관리는 독립적입니다. !퀴즈작동 / !퀴즈중지 / !낚시작동 / !낚시중지도 봇 계정만 사용합니다.

## NEXI 발로란트 명령어 ON/OFF

- **방별 초기값: OFF.** 해당 카카오톡 방에서 **봇 계정 본인**이 `!발로on`을 입력해야 발로란트 명령어가 작동합니다.
- `!발로off`를 봇 계정이 입력하면 다시 중지됩니다. 일반 채팅 참여자는 토글할 수 없습니다.
- 켜진 방에서만 `!스킨`, `!발로전적`, `!전적`, `!티어`, `!최근전적`, `!승률`, `!헤드샷` 조회를 허용합니다. 꺼진 방에서는 해당 명령어에 답하지 않으며 외부 API도 호출하지 않습니다.
- PostgreSQL `hz_rooms.data.valorant` JSONB 플래그를 사용하므로 재시작 후에도 방별 ON/OFF 상태가 유지됩니다. DB 연결 오류가 나면 조회를 허용하지 않는 fail-closed 방식입니다.
- 기존 게임·관리 설정과 독립적으로 작동합니다. `!게임on`만으로 발로란트 기능이 켜지지는 않습니다.

## NEXI 발로란트 스킨 조회

카카오톡에서 `!스킨 (이름)` 명령으로 발로란트 공개 스킨 도감을 검색합니다.
예: `!스킨 싱귤 밴달`, `!스킨 약탈 벤달`, `!스킨 프라임 팬텀`.

- 한국어/영문 이름, 줄임말, 흔한 오타를 유사도 검색합니다. 결과가 여러 개인 경우 후보를 보여주고 선택을 요청합니다.
- `valorant-api.com`의 한국어·영어 무기 스킨, 등급, 업그레이드 레벨, 크로마(색상), 미리보기 영상 주소를 읽습니다. 사용자의 Riot 계정이나 로그인 정보는 요구하지 않습니다.
- 스킨 정보와 **비교 사진 1장**을 순서대로 전송합니다. 사진에는 공개 데이터에 별도 이미지가 있는 기본형, 최종 업그레이드, 색상별 외형(최대 8칸)을 포함합니다. 실제 데이터가 단계별 외형을 구분하지 않으면 '업글 후' 사진을 만들어내지 않습니다.
- 사진은 공개 CDN의 PNG만 다운로드하고, 비교용 이미지는 기존 KakaoForge `client.sendPhoto`를 통해 전송합니다. 업로드 실패 시 원본 이미지 URL을 텍스트로 안내합니다.
- VP 가격은 공개 스킨 API에서 **개별 상품 정가를 제공하지 않으므로** 등급 기준 일반가를 참고용으로 표시하거나 '개별 가격 확인 필요'라고 안내합니다. 레디어나이트 업그레이드 비용도 추정하지 않습니다.
- 스킨 목록은 6시간 캐시, 이용자별 명령어 간격은 7초입니다. 스킨 검색은 기존 게임 `!상점`과 무관하고, 게임/관리 ON/OFF 상태와 관계없이 사용 가능합니다.

## NEXI 발로란트 전적 조회

대표 명령어: `!발로전적 닉네임#태그 [서버]` — 현재 티어, RR, 최고 티어, 최근 경쟁전 승률·헤드샷률·K/D/A와 전체 모드 최근 20경기 결과를 한 번에 전송합니다.
기존 `!전적`, `!티어`, `!최근전적`, `!승률`, `!헤드샷` 명령도 호환을 위해 계속 지원합니다.

서버는 기본적으로 `kr`이며 필요 시 `ap`, `eu`, `na`, `br`, `latam`을 지정할 수 있습니다.
Railway 서비스의 Variables에 다음 환경변수를 설정해야 합니다.

- `HENRIKDEV_API_KEY`: [HenrikDev Dashboard](https://api.henrikdev.xyz/dashboard/)에서 발급받은 개인 API 키. 절대 GitHub에 커밋하거나 채팅으로 전송하지 마세요.
- `VALORANT_APPROVED_PLAYERS`: 전적 공개에 동의한 플레이어의 Riot ID를 쉼표로 구분한 목록. 예: `User#KR1,Second User#AP1`. 계정 소유자와 동의 여부를 **운영자가 먼저 별도 검증**한 뒤 등록해야 합니다. 카카오톡 닉네임만으로 Riot 계정 소유자임을 증명할 수 없으므로 명령어로 자동 등록하지 않습니다.

키가 없거나 동의 목록에 없는 계정은 **외부 API에 요청을 보내지 않습니다.**
공개 동의를 확인하는 Riot RSO 연동은 구현되지 않았습니다. 공식적인 계정 소유자 확인을 자동화하려면 승인된 Riot 애플리케이션과 RSO 연동이 필요합니다.

데이터는 HenrikDev 비공식 Valorant API의 MMR v3와 Matches v4에서만 조회합니다.
승률은 API가 제공한 최근 경쟁전 가운데 승패를 판정할 수 있는 경기만 계산하며,
헤드샷률은 제공되는 유효한 명중 부위 데이터 기준으로 계산합니다. 데이터가 부족하면 임의 수치를 만들지 않고 '확인 불가'로 표시합니다.
재조회 캐시 2분, 사용자당 조회 간격 12초, 서버의 API 요청 상한을 적용합니다.
외부 API 키 및 플레이어 동의 설정이 없으면 실제 조회는 활성화되지 않습니다.

## 데이터 보존

기존 테이블·게임 기록을 지우지 않습니다. 신규 기능의 테이블만 추가합니다. 종전 게임 points와 주식/출석 wallet은 별도 잔액이었으므로 사용자 첫 이용 시 한 번만 합산하고 LEGACY_GAME_MERGE 기록을 남깁니다. 이후 게임과 웹은 같은 지갑을 사용합니다. 방 행과 지갑 행 잠금, 거래 트랜잭션, 메시지별 중복 방지로 동시 요청을 처리합니다. 오래된 물고기도 기존 가격으로 판매할 수 있습니다. 펫/낚시대 종류·가격·확률과 과거 인벤토리는 유지합니다. 낚시의 기존 즉시 보상과 판매 보상 방식도 유지합니다.

퀴즈는 기존 200문제를 유지해 총 400문제(일반상식·수학·넌센스)로 확장했습니다. 제한 60초, 첫 정답 10,000코인과 30 XP입니다. 낚시는 사진 없이 20종, 대기 2초, 기본 20 XP이며 기존 펫 보너스가 적용됩니다. 최대 레벨은 200입니다.

주식은 Yahoo 공급자의 조회 시세를 사용합니다. 시세가 15분 이상 지연되거나 정규장 구간 밖이거나 공급자 조회가 실패하면 거래하지 않습니다. 환율도 조회에 실패하면 임의로 만들지 않습니다. 목록은 지원 종목 목록이며 시가총액 전체 순위가 아닙니다. 주식 보유 순위는 매수원금 기준입니다. 가격 알림은 60초마다 확인하며 1회 발송 후 해제됩니다.

웹 홍보는 20분·30분 중 선택합니다. 한국 시각 기준 20분은 매시 00·20·40분, 30분은 00·30분에 전송합니다. 방 이름 옆 ON/OFF로 작동하며 ON 이후 다음 시간부터 전송합니다. 예약 시작 시간은 없습니다. 최근 5분 내 중복 실행과 슬롯별 중복을 차단합니다. 네트워크 응답이 모호한 실패는 중복 위험 때문에 자동 재전송하지 않습니다. 기존 봇 명령어의 5~120분 입력은 호환성을 유지합니다.

## 운영자 설정

[docs/운영안내.md](docs/운영안내.md)를 참고하세요. 비밀번호·DB 주소·카카오 인증 파일을 GitHub에 올리지 마세요. 관리자 비밀값이 없으면 로그인과 관리자 API는 잠깁니다. 공개 랭킹은 기본 비공개이며 공개 동의와 별명이 있어야 노출됩니다.

## 구조

- game/: 기존 게임, 코인·주식·퀴즈 확장 및 지갑 연결
- manage/: 기존 관리·출석
- shared/: 단일 메시지 수신, 공통 상태·이벤트·DB
- promotion/: 홍보 권한·계정별 QR 연결·암호화 보관·전송 기록
- api/: 인증, 공개/관리 API, HTTP 서버, 추가 스키마
- public-web/, admin-web/, promo-web/: 공개 사이트·전체 관리자·초대 회원 홍보 화면
- scripts/admin-setup.js: 본인 PC에서 관리자 비밀값 생성
- src/: KakaoForge 연결 소스
- test/: 회귀 및 격리 PostgreSQL 통합 테스트

## 검증

`npm test`, `npm run build`를 실행합니다. 테스트는 모의 연결과 PGlite의 격리 PostgreSQL 엔진을 사용합니다. 운영 DB의 데이터나 카카오톡 방에 테스트 메시지를 넣지 않습니다. 실제 카카오톡 멘션·삭제 이벤트, 실제 장중 시세 공급자 응답, 운영 환경 재배포 후의 게임 기록은 별도 현장 확인이 필요합니다. 관리자 대시보드는 수집된 값만 표시하며 외부 Railway 상태를 추정하지 않습니다.

홍보 웹은 이용자별 카카오 연결과 방 설정을 분리합니다. 운영자 봇의 계정·채팅방을 이용자에게 위임하지 않습니다. 방 제목은 TITLE 메타데이터만 사용하며 보이스룸 제목을 제외하고 상세 조회로 누락된 이름을 보완합니다. 실제 QR 승인 및 실계정 전송 확인은 이용자가 직접 진행합니다.
