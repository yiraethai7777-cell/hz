# GL BOT

카카오톡 게임·관리·홍보와 웹사이트를 하나의 PostgreSQL에 연결합니다.

## 실행

Node.js 22.8 이상 또는 24에서 `npm ci`, `npm start`를 실행합니다. Railway의 기존 DATABASE_URL, KAKAO_AUTH_PATH, 인증 파일 복원 명령은 유지합니다. hz-new.js가 봇과 HTTP 서버를 함께 실행하며 PORT는 Railway 값을 사용합니다. src/를 빌드한 dist/는 배포 시 생성합니다.

- `/`: 공개 게임 소개, 동의한 별명만 보이는 랭킹, 공지, 이용 안내
- `/admin`: 운영자 로그인 및 사용자·코인·채팅방·홍보·공지·감사 기록 관리
- `/promo/`: 초대받은 회원의 홍보 전용 웹. 모든 방 이름을 표시하며 지정받은 방만 제어합니다. [초대·사용 방법](docs/홍보웹-사용안내.md)
- `/health`: 게임/DB 초기화와 카카오톡 연결 상태
- `GL_WEB_ENABLED=0`: HTTP 서버만 비활성화

## 사용 명령어

봇 계정에서 !게임작동 / !게임중지, !관리작동 / !관리중지를 사용합니다. 게임과 관리는 독립적입니다. !퀴즈작동 / !퀴즈중지 / !낚시작동 / !낚시중지도 봇 계정만 사용합니다.

## 데이터 보존

기존 테이블·게임 기록을 지우지 않습니다. 신규 기능의 테이블만 추가합니다. 종전 게임 points와 주식/출석 wallet은 별도 잔액이었으므로 사용자 첫 이용 시 한 번만 합산하고 LEGACY_GAME_MERGE 기록을 남깁니다. 이후 게임과 웹은 같은 지갑을 사용합니다. 방 행과 지갑 행 잠금, 거래 트랜잭션, 메시지별 중복 방지로 동시 요청을 처리합니다. 오래된 물고기도 기존 가격으로 판매할 수 있습니다. 펫/낚시대 종류·가격·확률과 과거 인벤토리는 유지합니다. 낚시의 기존 즉시 보상과 판매 보상 방식도 유지합니다.

퀴즈는 기존 200문제를 유지해 총 400문제(일반상식·수학·넌센스)로 확장했습니다. 제한 60초, 첫 정답 10,000코인과 30 XP입니다. 낚시는 사진 없이 20종, 대기 2초, 기본 20 XP이며 기존 펫 보너스가 적용됩니다. 최대 레벨은 200입니다.

주식은 Yahoo 공급자의 조회 시세를 사용합니다. 시세가 15분 이상 지연되거나 정규장 구간 밖이거나 공급자 조회가 실패하면 거래하지 않습니다. 환율도 조회에 실패하면 임의로 만들지 않습니다. 목록은 지원 종목 목록이며 시가총액 전체 순위가 아닙니다. 주식 보유 순위는 매수원금 기준입니다. 가격 알림은 60초마다 확인하며 1회 발송 후 해제됩니다.

웹 홍보는 20분·30분 중 선택합니다. 한국 시각 기준 20분은 매시 00·20·40분, 30분은 00·30분에 전송합니다. 방 이름 옆 ON/OFF로 작동하며 ON 이후 다음 시간부터 전송합니다. 예약 시작 시간은 없습니다. 최근 5분 내 중복 실행과 슬롯별 중복을 차단합니다. 네트워크 응답이 모호한 실패는 중복 위험 때문에 자동 재전송하지 않습니다. 기존 봇 명령어의 5~120분 입력은 호환성을 유지합니다.

## 운영자 설정

[docs/운영안내.md](docs/운영안내.md)를 참고하세요. 비밀번호·DB 주소·카카오 인증 파일을 GitHub에 올리지 마세요. 관리자 비밀값이 없으면 로그인과 관리자 API는 잠깁니다. 공개 랭킹은 기본 비공개이며 공개 동의와 별명이 있어야 노출됩니다.

## 구조

- game/: 기존 게임, 코인·주식·퀴즈 확장 및 지갑 연결
- manage/: 기존 관리·출석
- shared/: 단일 메시지 수신, 공통 상태·이벤트·DB
- promotion/: 홍보 권한·스케줄·전송 기록
- api/: 인증, 공개/관리 API, HTTP 서버, 추가 스키마
- public-web/, admin-web/, promo-web/: 공개 사이트·전체 관리자·초대 회원 홍보 화면
- scripts/admin-setup.js: 본인 PC에서 관리자 비밀값 생성
- src/: KakaoForge 연결 소스
- test/: 회귀 및 격리 PostgreSQL 통합 테스트

## 검증

`npm test`, `npm run build`를 실행합니다. 테스트는 모의 연결과 PGlite의 격리 PostgreSQL 엔진을 사용합니다. 운영 DB의 데이터나 카카오톡 방에 테스트 메시지를 넣지 않습니다. 실제 카카오톡 멘션·삭제 이벤트, 실제 장중 시세 공급자 응답, 운영 환경 재배포 후의 게임 기록은 별도 현장 확인이 필요합니다. 관리자 대시보드는 수집된 값만 표시하며 외부 Railway 상태를 추정하지 않습니다.
