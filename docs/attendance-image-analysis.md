# 출석 이미지 사전 분석 및 로컬 구현

## 현재 범위

이미지 생성기와 읽기 전용 조회기를 PR #15로 올린 뒤, 사용자가 지정한 `테스트` 방으로 전송하는 관리자 테스트 버튼과 전송 모듈을 로컬에 추가했다. 테스트 버튼 변경은 아직 업로드·배포하지 않았다. 실행 파일, 기존 출석·코인 처리, 명령 라우터에는 연결하지 않았다. 실제 테스트방 전송을 확인한 다음 명령을 연동한다. Push·배포는 별도 승인이 필요하다.

## 기존 출석 구조

- `start.js → hz-new.js → shared/router.js → manage/index.js → manage/attendance.js` 순서로 처리한다.
- 현재 명령은 `!출석`이다. `#출석` 처리기는 없다. 이미지 승인 후 기존 처리 함수를 호출하는 별칭으로 추가할 수 있다.
- 정식 출석 테이블은 `hz_new_attendance`이며 기본 키는 `(room_id, user_id, attend_date)`다. 개인별 기록은 방별로 구분된다.
- 한국시간 기준 일자를 사용하며, 트랜잭션과 사용자별 advisory lock, 기본 키 충돌 처리로 중복 보상을 방지한다.
- 현재 보상은 `30,000 + (연속 일수 - 1) × 1,000` 코인이다. 이번 작업에서는 바꾸지 않았다.
- 지갑과 `ATTENDANCE` 코인 로그는 출석 기록과 같은 트랜잭션에서 저장된다. 이미지 작업은 이 거래가 완료된 뒤 수행해야 한다.
- 현재 `attend()` 반환값은 문자열이다. 이미지용 통계는 별도의 읽기 전용 조회 모듈에서 조회한다.
- 과거 관리 모듈의 `hz_attendance` 및 JSON 기록도 소스에 남아 있다. 현재 보상 경로는 `hz_new_attendance`를 사용한다. 두 계열 기록을 임의로 합치거나 이전 기록을 수정하지 않았다. 향후 과거 기록 통합을 원한다면 중복 기준을 별도로 정해야 한다.

## 이미지 전송 호환성

- KakaoForge에 실제 `client.sendPhoto(roomId, filePath, options)` 구현이 있다.
- 경로 문자열은 LOCO 업로드 과정을 수행한다. 버퍼를 직접 전달해 자동 업로드하는 구현은 없다. 버퍼를 attachment 객체처럼 넘기는 방식은 사용하지 않는다.
- 승인 후 전송 어댑터를 추가할 때 요청마다 `mkdtemp()`로 별도 임시 폴더를 만들고 PNG를 기록한 뒤, 전송 성공·실패 모두 `finally`에서 정리하는 방식이 적합하다.
- `send.js`는 기존 `client.sendPhoto`에 임시 PNG 경로를 전달하고 성공·실패 모두 해당 임시 폴더를 정리한다. `preview.js`는 봇에 연결된 방 중 이름이 정확히 `테스트`인 방이 한 개일 때만 예시 이미지 한 장을 전송한다. 60초 간격과 동시 전송 방지, 연결 상태 검사를 적용했다. 실제 DB를 쓰지 않는다.
- `/api/admin/attendance-image-test`는 기존 관리자 세션·CSRF 보호를 통과한 POST만 받는다. 관리자 대시보드의 명시적인 전송 버튼에서만 실행하며 공개 페이지와 홍보 회원 계정에는 노출하지 않는다.
- 아직 실제 카카오톡 전송은 하지 않았다. 사진 전송 성공을 확인하기 전에는 연동 완료로 보지 않는다.

## 신규 파일

- `manage/attendance-image/data.js`: 한국시간, 윤년·요일·달력, SVG 문자 이스케이프, 읽기 전용 출석 조회.
- `manage/attendance-image/render.js`: 기준 이미지 배치에 맞춘 SVG 및 PNG 버퍼 생성. 동시에 2장만 렌더링하고 대기열은 16개로 제한한다.
- `manage/attendance-image/assets/`: 기준 이미지에서 글자 없이 추출한 체크·달력 장식, 한글 글꼴, OFL 라이선스.
- `scripts/preview-attendance-image.js`: 운영 DB·카카오톡에 접근하지 않는 6종 PNG 예시 생성.
- `test/attendance-baseline.test.js`, `test/attendance-image.test.js`, `test/attendance-render.test.js`: 기존 보상·중복 방지, 조회·달력, 이미지·동시 처리 테스트.

## 패키지와 글꼴

- 이미 설치된 `@resvg/resvg-js`와 `pngjs`를 재사용한다. `sharp` 및 다른 Node 패키지는 추가하지 않았다. `package.json`, `package-lock.json`도 바꾸지 않았다.
- Google Fonts 공식 Noto Sans KR 가변 글꼴은 현재 렌더러에서 지나치게 얇게 표시되어 400·800 굵기의 고정 TTF를 만들어 포함했다. 실행 시 Python이나 폰트 변환 도구는 필요 없다.
- 폰트 출처: <https://github.com/google/fonts/tree/main/ofl/notosanskr>. 원본 OFL 문서를 함께 보관한다. 로컬 준비에 사용한 FontTools는 배포 의존성이 아니다.
- 시스템 글꼴 자동 탐색을 끄고 포함된 글꼴을 명시해 Windows·Linux 차이를 줄였다. 실제 Railway 이미지 렌더링은 배포 승인 후 추가 검증해야 한다.

## DB 변경과 정확성

새 테이블이나 컬럼은 필요 없다. 조회는 `REPEATABLE READ READ ONLY` 거래에서 해당 방·사용자의 출석과 실제 코인 로그를 읽는다. 두 기록이 같은 거래에서 `NOW()`로 저장되는 기존 구조를 이용해, 마이크로초를 보존한 출석 시각으로 실제 보상 로그를 찾는다. 실제 보상 로그가 없거나 여러 건이라 모호하면 보상을 추정하지 않고 `null`을 반환한다. 렌더러는 불명확한 보상이나 저장된 출석 기록이 없는 입력을 거부한다.

월별 달력에는 실제 조회된 날짜만 체크한다. 오늘의 테두리·체크는 오늘 출석 기록이 있을 때만 표시한다. 누적 출석은 현재 정식 테이블 기준이다. `readSnapshot`에 저장된 출석 일자를 명시하면 자정을 넘긴 처리에서도 오늘 날짜와 실제 출석 날짜를 구분하고 현재 월 달력을 표시한다. 실제 명령 연동 시 기존 거래가 결정한 일자를 전달해야 한다.

## 테스트와 남은 단계

6개 관련 테스트가 통과했다. 기존 30,000/31,000 보상, 동시 중복 출석, 이미지 오류 후 재시도, 한국시간 자정, 윤년, 평년 2월·10월·12월, 사용자별 기록 분리, SVG 주입 방지, 긴 닉네임 줄바꿈, 서로 다른 PNG의 동시 생성 등을 검증했다. DB 검증은 격리된 PGlite에 가짜 기록을 사용했으며 운영 데이터는 쓰지 않았다. 단일 연결 테스트에서는 advisory lock 대신 연결 직렬화를 사용하므로 운영 PostgreSQL 잠금 자체의 부하 검증을 대신하지는 않는다.

PNG 예시 6개는 1448×1086이며 원본 디자인의 체크·달력 장식만 재사용하고 모든 텍스트·통계·월별 달력은 새로 그린다. 긴 이름은 크기를 줄이거나 2줄로 표시하며 더 긴 이름은 말줄임한다. 6주 달력도 패널 안에 맞춘다.

미완료: 디자인 승인, 테스트방 실제 사진 1장 전송, 승인 후 `#출석` 연동, 실 PostgreSQL·카카오톡 및 Railway 재시작 검증, 별도 승인 후 Push·배포. 기존 `hz-bot.js`는 건드리지 않았다.
