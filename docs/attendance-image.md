# 출석 대시보드 운영 안내

## 사용법과 데이터

- 관리 기능이 켜진 방에서 `!출석`을 입력하면 하루 한 번 출석과 코인 보상을 저장한 뒤 개인별 PNG를 자동 전송합니다. 관리 기능은 기존 권한 정책에 따라 봇 관리자가 `!관리on`으로 켭니다.
- 이미지에 실제 닉네임과 `○○님 출석 완료되셨습니다!`, 오늘 날짜, 출석 날짜, 연속 일수, 총 누적 횟수, 실제 지급 코인 및 당월 출석 달력이 표시됩니다. 이름과 완료 문구는 두 줄로 배치합니다. 매우 긴 닉네임은 축소·줄바꿈·말줄임합니다.
- `!출석이미지`는 오늘 기록을 다시 그려 전송합니다. 출석 및 보상을 추가하지 않습니다. 전송 오류가 나도 완료된 출석을 취소하거나 보상을 다시 지급하지 않습니다.
- 같은 날 다시 `!출석`을 입력하면 중복 안내만 보내고 이미지나 보상을 추가하지 않습니다.
- 기존 `Asia/Seoul` 정책을 유지합니다. 저장한 출석 일자를 비동기 이미지 작업까지 전달하므로 한국시간 자정을 넘겨도 직전 출석 기록을 잃지 않습니다. 표시할 달력은 이미지 생성 시점의 한국시간 월입니다.

## 기존 구현과 통합

실제 경로는 `shared/router.js → manage/commands-v2.js → manage/attendance.js`입니다. 기존 `hz_new_attendance` 기본 키 `(room_id,user_id,attend_date)`와 사용자별 advisory lock, 출석·지갑·코인 로그의 동일 트랜잭션을 유지했습니다. 보상은 기존의 `30,000 + (연속 일수 - 1) × 1,000`입니다. 누적 횟수는 해당 방·사용자의 정식 출석 기록 수입니다.

과거 `hz_attendance` 및 JSON 출석 코드는 남아 있지만 이번 명령의 기록과 임의로 합산하지 않습니다. `#출석`은 라우터에서 거부되는 과거 명령입니다. 새 출석 테이블이나 별도 명령 처리기를 만들지 않았습니다.

`attendance-image/data.js`의 읽기 전용 스냅샷으로 실제 기록만 조회합니다. 출석 시각과 동일한 실제 코인 로그를 찾아 보상을 표시하며, 로그가 없거나 모호하면 이미지를 생성하지 않고 재시도 안내를 보냅니다. 임의의 보상을 추정하지 않습니다.

기존 장식 이미지와 Noto Sans KR 글꼴을 재사용하고 모든 닉네임·문구·날짜·통계·달력은 SVG로 매번 그린 뒤 PNG로 렌더링합니다. 장식을 포함해 흑백으로 출력합니다. 기존 `sendPng → client.sendPhoto` 업로드 및 완료 확인과 임시 파일 정리를 유지했습니다.

## 배포 설정

추가 환경변수, DB 마이그레이션, 패키지 설치 항목은 없습니다. 기존 `DATABASE_URL`, 로그인된 카카오톡 봇 연결, 방별 관리 활성화 설정이 필요합니다. `npm ci` 후 `npm run build`로 빌드하고 기존 실행 방식(`npm start`)으로 재시작합니다. 배포에 `manage/attendance-image/assets`의 장식 PNG·TTF·OFL 라이선스가 포함되어야 합니다. 임시 디렉터리 쓰기 권한이 필요합니다.

이번 환경에는 운영 봇 로그인 세션과 배포 서비스 연결이 없어 실제 카카오톡 수신 및 운영 재시작은 검증하지 않았습니다. 참고 대화 조회에서는 이미지 참조만 반환되고 첨부 파일은 제공되지 않아, 저장소에 포함된 기존 장식·배치를 기반으로 흑백 스타일을 적용했습니다.
